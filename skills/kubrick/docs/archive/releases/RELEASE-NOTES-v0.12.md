# Kubrick v0.12.0 Release Notes

Kubrick v0.12 converts the skill from a symbolic reference system into a CI-verified, standalone Hermes symbolic compiler with governed production feedback.

## Major capabilities

- Unified `kubrick` CLI and compiler orchestration.
- Deterministic registry-aware retrieval with project-ledger pressure, collision checks, production-cost handling, and fail-closed diagnostics.
- Private motif-structure graph with schema validation and disentangled geometry, function, and state layers.
- Structured anti-slop auditing and audience-facing privacy boundaries.
- Storyboard state propagation across ownership, objects, lighting, materials, convergence sites, and residue.
- Provider-neutral model-adapter packets and Grok Imagine prompt translation.
- Structured visual observations, dimension-specific fidelity reports, and targeted correction packets.
- Bounded correction-loop governance for progress, regression, and iteration limits.
- Pattern-use receipts and proposal-only pattern evolution.
- Canonical authority-transfer storyboard example.
- Stable-artifact repeatability verification in GitHub Actions.

## Governance

- Local outputs remain `PROPOSED`.
- Production-use receipts remain `OBSERVATION`.
- Evolution proposals cannot apply automatically.
- Private pattern and lexicon semantics remain outside audience-facing output.
- External model APIs, MCP, and Continuity Forge remain optional.

## Compatibility

The core remains a self-contained Hermes skill. Repository validation currently uses Python, PyYAML, and jsonschema. No external generation or vision provider is required.

## Release gate

The `v0.12.0` tag should be created only after:

1. all version declarations match `VERSION`,
2. README and changelog describe v0.12,
3. the default branch is green,
4. the release checklist is complete,
5. installation is verified in a clean Hermes skill directory.
